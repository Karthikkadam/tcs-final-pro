6	Booking a Service - Customer
(Web)		As a Customer I should be able to book a service from the application	In the booking service screen, below information of current user should be displayed
-Name
-Address
-Contact details
And system should able to capture the below information from the user.
- ReceiverName
- ReceiverAddress
- ReceiverPin
- ReceiverMobile
- ParcdelWeightInGram
- ParcelContentsDescription
- ParcelDeliveryType
- ParcelPackingPreference
- ParcelPickupTime
- ParcelDropoffTime
These fields need to be captured / calculated by the system
- ParcelServiceCost (Need to calculate the amount based on the choices done by the user)
-Parcel service cost can be calculated using the following formula 
-ParcelService Cost = Base Rate + Weight Charge + Delivery Charge + Packing Charge) *(1 + Tax Rate)
Breakdown of Each Component:
-Base Rate = Fixed starting cost (e.g., ₹50)
-Weight Charge = Cost per gram (e.g., ₹0.02 × parcel weight in grams)
-Delivery Charge =
Standard Delivery: ₹30
Express Delivery: ₹80
Same-Day Delivery: ₹150
-Packing Charge (depends on preference):
Basic Packing: ₹10
Premium Packing: ₹30
-Tax Rate = 5% (or as per business rules)
-Example Calculation:
Parcel weight: 2000g
Delivery type: Express Delivery
Packing: Premium Packing
Applying the equation:
 -Service Cost = (50 + (0.02 * 2000) + 80 + 30) * (1 + 0.05)
= (50 + 40 + 80 + 30) * 1.05 
 = 200 *1.05
= ₹210 
- ParcelPaymentTime (System date and time)
-After booking, it need to display a Booking Id and the relevant information's as acknowledgment and user should be redirected to the payment page for completing the booking

9	Pay Bill – Web		As a Customer, I should be able to pay for the parcel	1. Card Details Section
 • The page should have fields to enter Card Number, Expiry Date, CVV, and Cardholder Name.
 • Only valid card numbers of 16 digits should be accepted.
 • The CVV field should only accept 3 digits (or 4 for some cards like American Express).
2. Validation Checks
 • Card number, expiry date, and CVV should have front-end validation to prevent incorrect formats.
 • Expiry date should ensure the card is not expired.
 • All fields are required; submitting the form with missing fields should show appropriate error messages.
      • If the payment fails (e.g. incorrect CVV, expired card), an error message should be displayed.
 • The error message should be specific.
3. Validate the Payment Amount Display
 • The total amount due should be displayed clearly and prominently on the page before the customer submits the payment.
4. Confirmation Prompt
 • Once the user submits payment, a confirmation prompt should appear to review details before final submission.
 • The user should be able to cancel or confirm the payment.
5. Successful Payment
 • Upon successful payment, a success message along with the following details needs to be displayed:
     -Payment id
     -Transaction id
     -Transaction Date
     -Transaction Type(Credit/Debit)
     -Booking Id
     -Transaction Amount
     -Transaction status
 •There should be an option to download the receipt of the payment with all necessary details.
 • The confirmation page should include a link to return to the account dashboard or e-bill history.
  • If the officer is taking the booking, then the customer payment should be at office, after that only the booking status is changed

- Use web concepts for the necessary actions.

15	Booking Cancel- Customer
(Web)		As a customer I should be able to cancel  booking of a parcel	* As a customer, I want to cancel the booking of a parcel,whose delivery status is 'booked' using booking Id
Input fields on screen:
- Booking ID: An integer representing a unique, auto-generated value for each booking
- Cancel: Upon entering the Booking Id, the system will search for the matching  booking. If found, it will allow the user to cancel the booking  from the bookings table.
* Soft Cancel:
- Instead of permanently deleting the booking from the database, a booking status change  will be implemented.
- This means that the booking's status will be updated to 'cancelled' and the booking will no longer be visible to customers, but it will still be retained in the system.
- The admin should have the option to change the status in the future, restoring the booking to 'booked' status.
* After successful cancelling , a confirmation message such as "Booking cancelled successfully"should be displayed in green, showing the Booking ID  of the cancelled product.
* If the booking is not found based on the provided Booking  ID , store the error message and display such as "Booking cancel  failed, incorrect Booking ID".
